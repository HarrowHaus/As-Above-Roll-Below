# As Above, Roll Below — Content Scope & Authoring Spec

**Version:** 0.1  
**Status:** production scope target; exact launch counts may change with budget/playtest needs

The game should become replayable through interactions and encounter variety, not by burying the player under thousands of low-impact objects.

---

# 1. Vertical slice content target

## Characters
- 1 playable character
- 2 Level 3 Technique options
- Level 5 Technique may be included if slice progression reaches it naturally

## Floor
- Floor I: Thresholds

## Enemies
- 8 normal/tough enemies
- 2 elites
- 1 boss for final review build

## Loot
- 12 Artifacts
- 8 Gear
- 6 Contraband

## World
- 3 Events
- 1 Shop system
- constrained route map

The slice is enough to prove a build ecosystem, not a content-complete mini-game.

---

# 2. Initial full-release target envelope

Target, subject to production reality:

## Characters
4 playable characters.

Each character:
- defining starting ability
- starting Gear identity
- 2 Level 3 Technique choices
- 2 Level 5 Technique choices

Total authored Techniques: 16.

## Floors
4 primary Floors/themes.

## Normal/tough enemies
Target 32–40 total.

Approximately 8–10 per Floor before cross-Floor variants/rare encounters.

## Elites
Target 8 total, roughly 2 per Floor.

## Bosses
Target 8 boss encounters, roughly 2 possible bosses per Floor where production allows.

A run sees one boss per Floor.

If budget requires fewer bosses at launch, prefer 1 excellent boss/Floor over palette-swapped variants.

## Artifacts
Target 48–60.

## Gear
Target 24–30.

## Contraband
Target 18–24.

## Events
Target 28–40.

The content engine should support expansion without changing fundamental systems.

# 3. Character mechanical roles

Characters all use the same core 4d6 / commit-two rules.

Characters differ through one defining bias, not separate games.

Launch mechanical coverage should include:

## Manipulation / generalist
Reliable BUMP/FLIP-style control. Best onboarding character.

## Pattern specialist
Values doubles, sequences, parity, exact totals.

## Greed / anomaly specialist
Rewards unusual outcomes and stronger Fight/Spoils tension.

## Conventional / equipment specialist
Stronger interaction with Gear/Contraband/economy, fewer supernatural manipulations.

Final identities/names belong to content writing and Art Bible.

---

# 4. Technique structure

Each character has a fixed pair at Level 3 and a fixed pair at Level 5 in baseline design.

Why fixed pairs:

- character identity remains learnable;
- Level choice is meaningful without another giant random pool;
- four possible Technique combinations already multiply run identity;
- loot remains the primary random build system.

Technique requirements:

- one sentence if possible;
- no inventory slot;
- character-specific;
- changes a recurring decision;
- no generic `+10% damage`.

---

# 5. Artifact portfolio

Artifacts are the largest persistent-item pool.

Target 48–60 should roughly cover:

- 15% Greed/Spoils
- 15% Pattern
- 15% Manipulation
- 10% LOCK/persistence
- 10% Defense/risk permission
- 10% Enemy interference
- 10% Economy/reward
- 15% hybrids/strange build anchors

These are portfolio checks, not strict quotas.

At least half the Artifact pool should interact directly with dice, Fight/Spoils interpretation, or manipulation.

---

# 6. Gear portfolio

Target 24–30.

Approximately balanced across:

## Weapons
- margin amplification
- pair pattern bonus
- exact-total attacks
- high/low-face tactics

## Armor
- first-hit mitigation
- conditional mitigation
- tie/loss manipulation
- recovery/risk conversion

## Utility
- economy
- reward manipulation
- tie rules
- Contraband support
- route/Event interaction

Gear should be more immediately legible than Artifacts.

---

# 7. Contraband portfolio

Target 18–24.

Functional distribution:

- player-die correction
- enemy-die interference
- emergency defense
- healing/recovery
- temporary rule bypass
- reward/economy intervention

Contraband must solve an immediate visible problem. Avoid consumables that amount to tiny invisible buffs for three rooms.

---

# 8. Item complexity budget

## Tier I
One trigger + one action preferred.

## Tier II
One trigger with multi-part consequence, or two tightly linked rules.

## Tier III
May create a new mini-engine but must remain inspectable in a tooltip without a paragraph of exceptions.

If an item requires a flowchart, simplify it or reserve it for an authored boss/event rather than inventory loot.

---

# 9. Enemy portfolio

Every Floor's ordinary roster should cover multiple Instincts and tactical problems.

Per Floor target:

- 2 straightforward baseline enemies
- 2 manipulation/locking enemies
- 1 greed-pressure enemy
- 1 pattern enemy
- 1 defensive/tie enemy
- 1 unusual Floor-specific rule enemy
- optional rare/reference encounter

Do not create eight enemies that all differ only by HP and dice count.

---

# 10. Elite portfolio

Elite must introduce an authored tactical premise.

Examples of valid Elite axes:

- strong dice selection + exploitable weakness
- two-state Instinct
- meaningful enemy manipulation
- escalating round rule
- pressure on a common greed strategy

An Elite is not `normal monster × 2 HP`.

---

# 11. Boss portfolio

Bosses should explore systems the Floor taught.

Each Boss design file must define:

- thematic/system thesis
- custom dice behavior
- HP
- phases/states
- transition rules
- unique rule per state
- expected round range
- failure/readability risks
- premium reward pool
- accessibility/preview requirements

Bosses may violate ordinary enemy templates when doing so is the point.

---

# 12. Event portfolio

Target 28–40 full release.

Event functional coverage:

- HP-for-power bargain
- Coins/economy
- item replacement/transformation
- Contraband gain/use
- route information
- build-tag contextual choice
- uncertain cast/roll event
- research/lore encounter
- harmless comic breather with real choice

No event category should dominate the pool.

---

# 13. Reference-derived vs original content ratio

The game must not become a cryptid/conspiracy checklist.

Working content balance:

- fantasy/dungeon language
- Below-native originals
- folklore/Forteana
- occult/esoteric references
- institutional/conspiracy-history references
- strange documented objects/history
- wholly invented bureaucracy/procedural absurdity

The deeper Floors should trend increasingly original/Below-native.

Real-world reference status is governed by CONTENT_RESEARCH_BIBLE.md.

---

# 14. Floor identity

Every Floor must define:

- mechanical teaching/problem theme
- environment/material language
- enemy rule distribution
- Elite identity
- boss system thesis
- Event pool bias
- research/reference domains allowed
- native Below ecology development

A Floor theme cannot be art-only.

Floor I current preferred motif: **Thresholds**.

---

# 15. Item naming/writing

Rules text first.

Name/flavor cannot rescue unclear mechanics.

Every item record has:

- display name
- exact rules text
- category
- tier
- trigger/timing
- tags
- short flavor line optional
- art brief
- provenance/reference ID if relevant

Humor belongs primarily in naming/flavor and in the exact absurdity of the rule, not in ambiguous mechanical wording.

---

# 16. Content unlock philosophy

The initial unlocked pool must already form a complete good game.

Meta progression may reveal:

- stranger Artifacts
- new characters
- additional enemy variants
- alternate bosses
- Events
- difficulty modes

Do not deliberately make early runs boring so unlocking content feels like improvement.

---

# 17. Pool growth and dilution

Adding content can make a roguelite worse by diluting synergies.

Every expansion/new pool entry must answer:

- what archetype does it support?
- what other effects can it interact with?
- does it crowd out foundational pieces?
- does generator weighting need adjustment?

Unlocking an item should not silently reduce the chance of seeing every build anchor to useless levels.

Possible later controls:

- character-biased pools
- tagged reward events
- Shop targeting
- limited pool presets/challenges

Do not solve dilution by secretly forcing perfect synergy drops.

---

# 18. Content QA checklist

Before an item/enemy/event is approved:

- mechanically valid in data schema
- rule text matches actual effect
- timing unambiguous
- one clear reason to take/fight/choose it
- no accidental duplicate of existing mechanical role
- interactions with at least 3 relevant existing pieces reviewed where applicable
- balance simulation possible
- art requirement feasible
- reference/provenance checked if needed
- humor does not rely on factual error

---

# 19. Authoring order

For each new Floor/content batch:

1. define mechanical gaps
2. author rule skeletons without names
3. simulation/sanity pass
4. assign world/reference identities that fit
5. provenance research
6. write final names/flavor
7. art briefs
8. implementation data
9. runtime testing

This prevents lore from forcing bad mechanics and mechanics from abusing real references.
