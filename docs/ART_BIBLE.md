# Art Bible

**Status:** C-stage scaffold. Final visual production begins after the Content / Research Bible establishes the world and reference boundaries.

## Visual thesis

**As Above, Roll Below** should look like a deeply serious fantasy/occult game made by people with excellent taste and catastrophic subject matter.

The current target is a fusion of:

- polished modern indie-game readability;
- 1990s fantasy RPG sourcebook illustration;
- underground / photocopied zine contamination;
- conspiracy-document marginalia;
- esoteric geometry used with actual restraint;
- tactile physical dice;
- occasional mundane institutional detail treated with the same dignity as monsters.

The game must **not** visually imitate Munchkin's doodle/cartoon language.

---

## Core art principle

The production takes the joke seriously.

A ridiculous enemy should not automatically receive intentionally bad artwork. The contrast between high craft and absurd content is part of the identity.

---

## Character production requirement

Recurring player characters require locked model sheets before production sprites.

Each character sheet must define:

- front view;
- 3/4 view;
- side view;
- back view;
- silhouette;
- head / face construction;
- hand construction;
- body proportions;
- equipment attachment zones;
- material callouts;
- color/value hierarchy;
- idle pose;
- attack pose;
- hit pose;
- death pose;
- scale comparison.

Generated art is not accepted merely because an individual image is attractive. Recurring characters must remain recognizably the same person across every asset.

---

## Monster production requirement

Monsters may vary more dramatically than player characters, but must obey a shared rendering language.

Each Vertical Slice enemy needs:

- canonical silhouette;
- reference/provenance notes where relevant;
- front/3-quarter combat presentation;
- scale relative to player;
- material/texture notes;
- readable combat pose;
- damage reaction;
- death/resolution state;
- UI portrait/crop guidance.

Real-world-derived monsters must be visually based on verified features rather than vague pop-cultural approximation.

---

## Dice

Dice are central characters.

Requirements:

- physical/tactile appearance;
- readable pips plus optional numeric accessibility treatment;
- unambiguous selected/unselected states;
- enemy and player dice immediately distinguishable without relying only on color;
- convincing short roll/impact animation;
- legible at mobile scale;
- manipulation effects must visibly communicate BUMP, FLIP, LOCK, COPY, and related verbs.

Do not bury the dice under excessive particle effects.

---

## UI direction

The UI should feel unusually expensive for the ridiculous material.

Working language:

- restrained occult geometry;
- archival/document edges;
- diagrammatic rules notation;
- physical-table tactility without literally simulating a tabletop;
- clean combat arithmetic;
- strong typographic hierarchy;
- minimal permanent chrome.

The combat screen must privilege the decision:

**Monster locked dice → player roll → Fight pair → Spoils pair → predicted margin.**

---

## Symmetry and title language

The title **As Above, Roll Below** supports controlled mirrored motifs:

- above / below;
- reflection;
- inversion;
- paired geometry;
- die faces and opposite faces;
- descent.

Avoid turning every screen into a pentagram poster. Esoteric visual language should feel informed, not generic.

---

## Environment approach

The Dungeon should become stranger by layer while preserving visual continuity.

The environment system needs:

- shared architectural grammar;
- floor-specific material shifts;
- readable combat staging;
- space for enemies with wildly different silhouettes;
- environmental evidence of accumulated realities without becoming visual clutter.

The Vertical Slice gets one complete environment at finished quality.

---

## Animation standard

Combat is turn-based but should feel physical.

Minimum animation families:

- player idle;
- enemy idle;
- dice throw / settle;
- die selection;
- die manipulation;
- clash;
- margin-damage impact;
- player hit;
- enemy hit;
- enemy defeat;
- boss phase transition;
- item trigger;
- reward reveal.

Standard interactions should be fast. Spectacle is reserved for important moments.

---

## VFX

VFX communicate rules first and mood second.

A manipulation effect must tell the player exactly what happened to which die.

Avoid:

- screen-filling glow for ordinary actions;
- illegible particle fog;
- color-only state communication;
- constant camera shake;
- effects that make numerical comparison harder.

---

## Asset consistency pipeline

Before final asset generation:

1. lock character/monster reference sheet;
2. lock camera and perspective;
3. lock value range and material treatment;
4. create first production asset;
5. compare against reference sheet;
6. revise reference sheet if required;
7. only then batch adjacent assets.

Every generated asset must be reviewed for silhouette, anatomy, costume continuity, provenance accuracy, edge quality, transparency/masking, and in-game readability.

---

## Technical delivery targets — to be finalized

The final Art Bible must specify:

- canvas dimensions;
- sprite/native render scale;
- target browser resolutions;
- transparent-background requirements;
- animation frame or skeletal-animation approach;
- texture compression;
- UI export sizes;
- naming conventions;
- atlas strategy;
- source-file storage;
- generated-reference provenance.

Do not decide these only by aesthetics; implementation architecture and performance must inform them.
